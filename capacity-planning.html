Capacity planning

I built a capacity-planning prototype to replace custom Excel spreadsheets. Managers can test assignments, save plans for later, and commit changes to the connected systems when they are ready.

The planning problem

Managers used custom Excel spreadsheets because the existing project management and portfolio tools did not provide the capacity detail or flexibility they needed. They also had to enter project information in other systems.

They needed to see over- and underutilization, identify people who could be borrowed from another team, and explore assignments before committing to them.

Resource decisions

I wanted managers to see where another team had capacity to help, so they could consider borrowing resources before relying on overtime, contractors, or additional headcount. When existing capacity cannot cover demand, overallocation across a planning period also gives them evidence for a staffing request.

My role

I led stakeholder discovery and requirements work across four manager organizations and approximately seven teams. I designed the workflows, data architecture, interactions, and visual presentation, built the prototype, and managed its scope.

Why the existing tools fell short

I evaluated five solution paths, including Wrike and an internally developed PPM tool. The internal tool supported some of the required functions, but changes could affect production systems before a manager had finished evaluating an option.

I consolidated the shared requirements and designed one planning workspace that exchanges project information with both existing tools. Managers enter the data once; other teams can continue using their established systems.

Development

I built and deployed a functional prototype in under two weeks. The work included the capacity model, front-end development, REST API integrations, project synchronization, and a visual system for comparing utilization. I used GenAI to assist with engineering.

Planning capabilities

Load previews
Assignments and rebalancing recalculate the load as managers work. A monthly heat map uses a seven-tier scale, with portfolio, team, individual, and project views.
Saved plans
Managers can save without committing, then resume planning later. Changes reach production only when committed.
Team-specific requirements
One team needed an established ROI calculation that influenced availability and synchronized with another tool. Other managers could remove that field from their view. View preferences persist with each manager’s login.
Worker-group filters
A separate filter identifies vendors, contractors, and hourly development employees so managers can consider pay and contract implications when assigning work.
Shared assignments
Multiple assignees can have independent allocations. Overload alerts and visibility into capacity across teams support rebalancing.
Intake support
Priority scoring and contractor offload opportunity detection support assignment planning.

Tools

HTML, CSS, JavaScript, REST APIs, GitHub Enterprise, internal enterprise hosting, Claude, and project management platform integration.

Current status

The scope expanded from a single-team tool to an organization-wide initiative. It is in stakeholder testing and is being considered as a standalone platform or as part of another project portfolio management tool.
